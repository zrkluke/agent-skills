# 動手實作：階段 6～8

文章列出後三階段，但沒有逐項指定操作；以下採最少的執行約定，細節沿用目標專案流程。

## 6. 工作區：準備可辨識的執行位置

核對設計、大綱、計畫及程式版本。依專案規則準備分支／worktree 與必要環境；已有適合的工作區就沿用。記錄實際路徑、分支與起始版本，保留原有未提交內容。

## 7. 實作：完成一個增量，就驗證一個增量

按大綱／計畫完成一個可驗證增量，就執行其必要檢查，通過才接續相依工作。測試範圍與提交方式沿用專案規則，不新增本技能專用的測試套數或提交關卡。

結果寫回既有大綱／計畫。若新發現推翻設計，先修正對應決定與受影響步驟，避免程式與文件分歧。

使用者可以要求逐段審閱或連續完成多段；保留已約定的人工檢查點，不自行增加每步確認。測試通過代表相應自動檢查通過，不能替代實際程式碼審查。

## 8. PR：整理人能有效審查的差異

讀取相對正確目標分支的完整淨差異及必要相鄰程式，核對設計與驗收條件，讓人能閱讀真正改動的程式碼。

提供問題與改變後的行為、建議閱讀位置、實際驗證及必要風險；不把代理審查或測試通過寫成人已閱讀。

依已有授權建立／更新 PR；未授權外部寫入時，交可審閱的差異與 PR 草稿。提交、推送、合併與發布沿用使用者授權及專案規則，不自行增加操作權限。
